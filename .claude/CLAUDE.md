# Dev Team — ამ პროექტის წესები

ეს პროექტი იყენებს Dev Team-ს. ზოგადი წესები და ტექნიკური სტანდარტი — გლობალური kit-იდან (`~/.claude/CLAUDE.md`, `project-standard` skill). State — kit-ის ფორმატით: `PROJECT.md` (მოთხოვნები, API Contract, Decision Log, Accepted Risks) და `PROGRESS.md` (task-ები owner-ით და ფაილებით, Backlog, Blockers, Run State).

ბრძანებები: `/auto` (ბოლომდე), `/audit` (მხოლოდ შემოწმება → `AUDIT.md`), `/fix` (აუდიტის გასწორება). kit-ის `/next-task` და `/finish-check` ამ პროექტზეც მუშაობს.

## სიმძიმე (ყველგან ერთნაირი)
- **critical** — მონაცემების დაკარგვა ან გაფუჭება, უსაფრთხოების დარღვევა, tenant-ების იზოლაციის დარღვევა, ფული/მარაგი არასწორად, მთავარი ფუნქცია გაფუჭებულია
- **should-fix** — `PROJECT.md`-ის წესი ირღვევა, ან ჩვეულებრივ გამოყენებაში ჩნდება შეცდომა ან არასწორი შედეგი
- **nit** — ყველაფერი დანარჩენი

**Done** = 0 critical და 0 should-fix. nit-ები Backlog-შია.

## პატარა ამოცანები
ერთი ფაილი, ერთი ბაგი, მცირე ცვლილება — თავად ან ერთი owner დეველოპერით. მთელ გუნდს ნუ გამოიძახებ: subagent-ები ლიმიტს ხარჯავს.

## არასდროს
- `.claude/` საქაღალდის ნებისმიერი ფაილის შეცვლა
- პროცესის მოკვლა სახელით (`taskkill /IM`, `pkill`, `killall`) — მხოლოდ PID-ით
- push, deploy, publish, მონაცემების წაშლა, გლობალური ინსტალაცია
- ტესტის ან შემოწმების წაშლა/გამოტოვება, რომ „გაიაროს"
